# HTTPS と証明書

## HTTPS ってなに？

お手紙でたとえます。

- **HTTP** は **ハガキ** です。届くまでに通る人は、誰でも中身を読めてしまいます
- **HTTPS** は **カギつきの箱** です。途中の人には中身が見えず、受け取った相手だけが開けられます

この wrapper では、合言葉（トークン）を毎回送ります。HTTP だと合言葉が丸見えになるので、HTTPS を使います。

## 証明書ってなに？

カギつきの箱を送る前に、「相手は本当にあのマシンなのか」を確かめたいですよね。ニセモノに送ったら困ります。

そこでサーバーは「ぼくは本物だよ」という **名札** を見せます。これが **証明書** です。

## 証明書は 2 つのものでできている

| もの | たとえ | ファイル |
|---|---|---|
| **秘密鍵** | 自分だけが持っている本物のハンコ。人に見せてはいけない | `server.key` |
| **証明書** | 名札。名前と、ハンコを確かめるための見本が書いてある。誰に見せてもいい | `server.crt` |

証明書は、いつもこの流れで作ります。

1. 秘密鍵（自分のハンコ）を作る
2. 名札を書く
3. 名札に **誰かがお墨付きのハンコを押す**

3 で **自分でハンコを押す** のが簡易な方法、**先生（認証局）に押してもらう** のが正式な方法です。違いはここだけです。

## どちらを使う？

| | [簡易：自己署名](https-self-signed.md) | [正式：認証局](https-ca.md) |
|---|---|---|
| ハンコを押す人 | 自分 | 認証局（先生） |
| 必要なもの | なし | ドメイン名（Tailscale なら不要） |
| 警告 | 出る（curl では `-k` が必要） | 出ない |
| 有効期限 | 自分で決める | 90 日ほど（更新が必要） |
| 向いている場面 | 家や社内で自分だけ使う | 他の人や機器から安心して使う |

LAN の中で自分だけが使うなら、簡易な方法で十分です。
